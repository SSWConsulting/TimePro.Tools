# 0.3.2

Diagnostics
- Every API call now identifies the client: `User-Agent: timepro-cli/<version>`, the command being run, whether it came from the CLI or the MCP server, and a unique request id. Errors show the request id (`requestId` in `--json`, a `request id:` line otherwise) so a failure can be matched to server logs.
- A local command log is kept at `~/.config/timepro-cli/logs/commands.jsonl` (rotated, no arguments, notes, ids or keys). Disable with `telemetry.localLog: false` in `config.json`.
- `--verbose` prints the API host and request ids to stderr.

Command line
- Unknown options are now errors instead of being silently ignored, so a mistyped flag such as `--iteraton` no longer runs the command without it. Commands that never supported `--json` (for example `login`, `logout`, `tenant set`, `ts export`, `whats-new`) now reject it rather than ignoring it.

Timesheets
- `tp ts check` says when suggestions are still waiting to be accepted (`All days covered; 3 suggestions still need accepting`) instead of "All clear". `--strict` treats pending suggestions as errors. `--json` adds `pendingSuggestions`.
- `tp ts export` now exports only your own timesheets by default. Use `--emp-id` for another employee or `--all` for the whole company export, which warns with the row count.

Leave
- `tp leave list --filter` validates its value and lists the valid ones; `ALL` returns upcoming and past entries together.
- `tp leave update` and `tp leave cancel` refuse requests that are already cancelled, pending cancellation, or declined, before calling the API.
- `tp leave cancel` reports that the cancellation was requested and explains that TimePro completes it a few minutes later. `--wait [seconds]` polls until the request reads `Cancelled` (exit 0) or times out (exit 2).

Skills
- Generated skill descriptions are now one-sentence triggers. Installed skills report as outdated; regenerate with `tp skills create`.
