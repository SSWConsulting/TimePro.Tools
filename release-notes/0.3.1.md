# 0.3.1

Timesheets
- `tp ts update` and `tp ts accept` accept `--iteration <name-or-id>`. Accept fails before writing when the project needs an iteration and none can be resolved, and lists the available ones.
- Updating or deleting a suggested entry is now refused locally with a hint to accept it first, instead of a bare 400 from the API.
- `ts create`, `ts update` and `ts accept --json` return the saved entry, including its id. `ts update --json` no longer prints `null` on success.
- The MCP `update_timesheet` tool now preserves every field it did not change. Previously it could wipe iteration, hours, dates and other fields on the server.
- `--less` reports `--less expects whole minutes` instead of a conversion error, and negative or blank values are rejected on create as well as update.

Tenants and environments
- `--env prod` only ever targets a config whose API host is production. Any other environment name refuses a production config. Mismatches fail with the config file, its API URL, and the fix.
- `tp tenant list` shows the config file name, API URL and environment, and marks the active tenant correctly. `--json` adds `file`, `isActive`, `apiUrl`, `isProduction`. `tp info --json` reports the effective `apiUrl` and `isProduction`.
- Connection failures (refused, timeout, DNS) name the active tenant file, its API URL, and how to switch. `--json` adds `tenant` and `apiUrl` under `error`.

JSON output
- Parse errors such as an unknown command or an unbindable option now honour `--json`: the error envelope goes to stdout with exit code 1. Without `--json`, the message goes to stderr instead of stdout.
- `tp rate get --json` returns the same keys on a hit and a miss (`found`, `date`, `clientId` always present).
- `tp project list --json` no longer includes the empty placeholder row with a null id.
- `tp ts get --from/--to --json` labels the range `from`/`to`; `--week` keeps `weekStart`/`weekEnd`.

Errors and help
- API errors now carry the server's explanation in `detail` (for example `Entity ClientInvoice with ID 42 not found`) on both the human and `--json` paths, instead of `detail: null`.
- Unknown commands suggest the closest match and list the valid subcommands, for example `Unknown command 'list'. Did you mean 'get'?`.
- `tp info` prints the correct refresh command for globally installed skills (for example `tp skills create .codex --global`), and `tp skills create . --global` is refused unless `--force` is given, so it no longer creates a stray `~/skills` folder.

Leave
- Half-day and other partial-day requests now derive their start and end from the workday times, so a request that `--dry-run` approves is one the server accepts. Times that are not on the hour or half-hour are rejected locally with the server's message, and single-digit hours such as `8:30` are accepted.

Accounting
- `tp recurring list` and `recurring get` no longer crash on the recurrence `unit`; it is shown as `year`, `month` or `day`, and the detail view now shows interval, day of month, next invoice date and products.
- `tp receipt list` and `tp receipt get` return real values. `receipt list` rows now carry `paidTotal` and an `invoiceIds` array, and `receipt get` returns the receipt under `receipt` with payment methods and totals. Scripts reading the old zeroed `invoiceId`/`paid` fields need updating; the generated accounting skill was revised accordingly.
